## 2. Decisions

- **One lookup for enum labels.** `EnumLabels.label` is the single place every renderer-facing path asks; `Labeled` lets an enum describe itself, the bundle-key convention localises without code, and the prettified name is always a sane fallback. The nodes module's editors delegate to it, so `OutlineView`, the Properties window, `ComboBox`, `ButtonGroup`, `Table` cells and `PropertyGrid` show the same label and icon for the same constant. The `cell` decoration is separate from the editable text (`getValueAsCell` vs `getValueAsText`), so a styled display never breaks typing.
- **What a gesture does is decided per component.** A drop or drag arrives as an event on the session thread. Components whose model is the board itself apply it first and then report (`Kanban` card positions, `Diagram` node positions) so the UI stays consistent even without a listener; components whose model is the application's only report (`Calendar` dates, `Diagram` connections/drops/deletes, `OutputView` links) — the listener decides. The documentation calls this out so the pattern is predictable.
- **Defaults stay off the wire.** `Property` defaults are never sent (a `create` carries only set properties), so renderers treat a missing prop as the default. Two components needed a client-side copy of a non-trivial default (`ColorPicker.PALETTE`, `Diagram.GRID`).
- **Lazily extended renderers.** The bundler concatenates renderer files in registry order, which is not guaranteed to put `wb.Table` before `wb.TreeTable`; subclass renderers therefore set their prototype on first `create` rather than at registration. `Table.decorateRow` and `Panel`'s `wb-panel-keep` are the two server/client hooks the subclasses needed.
- **The diff is computed once, on the server.** `LineDiff` (Myers' O(ND), common prefix/suffix trimmed first) produces the edit script; folds are applied on the server from `CONTEXT`, so the client renders what it gets and only expands folds locally. 2 × 300 lines diff in well under a millisecond.
- **The output view is a ring buffer on both sides.** `MAX_LINES` bounds the server list and the DOM; appends are coalesced per flush (`beforeFlush`), the whole buffer is re-sent on a full `init` (`resync`), and follow-tail is client-owned so a reconnect does not yank the scroll position.
- **Markdown belongs to the UI module.** The editor's preview must match help pages exactly, so `Markdown` moved to `org.webbeans.ui.text`; the help module imports it from there (no behaviour change).
- **Quick Search is a registry folder, not a hard-coded list.** Providers are instances under `QuickSearch/Providers`; the action is a normal registered action with a shortcut; the box is a component in the overlay slot. Results carry a `Runnable`, so a provider can do anything (open a window, run an action with the global context, navigate help) without the box knowing.
- **No map component.** A tile map needs a vendored client library (Leaflet) that cannot be fetched offline here; `Scene3D`'s on-demand `/wb/res/` loading is the pattern to use when one is available. Also deferred: WYSIWYG rich text (Markdown covers the need), a diagram minimap (flag reserved), edge routing, resizing timed calendar entries.
