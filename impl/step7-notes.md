# WebBeans — Step 7 Implementation Notes (v0.1)

What was built for roadmap step 7 (Scene3D), how it maps to `design/scene3d.md` (now v0.3, rewritten as built), and where it deviates. Source: `webbeans-step7.zip` (112 JUnit tests; `webbeans-demo/e2e/scene3d.js` plus the step 3–6 scripts drive headless Chromium, WebGL through SwiftShader).

## 2. Shape as implemented

- Package `org.webbeans.scene3d` in module `webbeans-scene3d` (design: `org.webbeans.api.scene3d` / `org.webbeans.modules.scene3d`). Depends on `webbeans-windows`, `webbeans-actions` and `webbeans-nodes` (window and explorer bridge live in the same module).
- Colours are `0xRRGGBB` ints (no `Color` class); vectors are the immutable `Vector3`/`Quaternion` value types.
- Batching: nodes report changes to their scene (`nodeAdded`/`nodeSet`/`nodeRemoved`); the scene keeps one pending op per node id, registers one `UI.beforeFlush` task and emits a single `call("scene", {...})`. An `add` is generated from the node's *current* state at flush time, so sets after an add cost nothing; definitions (`texs`, `mats`, `geoms`) are collected while node ops are built and go first in the payload; a resync (`attached()`/`resync()`) sends `reset: true` with the whole tree, all definitions, camera, controls and every running animation. Removing a subtree sends one `remove` (children whose ancestor is being removed are skipped).
- Cameras and controls are not nodes: `Camera` (position/target/up/near/far + projection) and `Controls` are value objects owned by the scene, sent as `camera`/`controls` members when dirty. `flyTo` updates the server camera at once and sends an animated `cmd`; user interaction reports back through `camera` events when the gesture settles and updates the server copy before listeners run.
- Environment settings are ordinary component properties (`BACKGROUND`, `FOG`, `GRID`, `SELECTION`, ...) rather than an `env` member, so they are part of the normal property stream and survive `init` without special handling.
- Blobs: `Geometry.buffer().build()`, `Texture.image(bytes)` and large instance arrays go into `BlobStore` and are referenced by sha256; the browser fetches `/wb/blob/<id>` (cacheable, immutable) and caches per page. Primitives travel as `{prim, args}`. Geometry ids are derived from the content (`g` + 16 hex of the hash), material ids are global counters (`m7`), texture ids hash url + options.
- Drags: the client solves the constraint locally for smoothness and reports `start`/`move`(throttled)/`end`; the server re-validates with `DragConstraint.apply(start, reported)`, applies the result to the node *before* listeners run (`DragEvent.getPosition()` is the validated position), and after listeners either echoes the corrected position (when it differs from what the client reported or the drag ended) or snaps back to the start when a listener called `reject()` or the node is not draggable.
- Animations run on the browser clock; `moveTo`/`scaleTo`/`path` completions report the final transform (`animDone`) which updates the node silently and runs `onComplete` on the session executor.
- `Scene3DTopComponent` mirrors `ChartTopComponent` (toolbar of simple actions + `Actions.forPath("Scene3D/Actions")` bound to the window lookup); `Scene3DChildren` listens to the scene (`SceneListener`) and keeps `Children.Keys` in sync; `Node3DNode` exposes name/type/visible/x/y/z/scale and renames through the scene node; `bindSelection` ties an `ExplorerManager` to `setSelection`/`PICK` with a re-entrancy guard.

## 3. Platform fixes found on the way

- A programmatic explorer selection of a node whose parent was collapsed was invisible: `NodeView.pushSelection` now expands the ancestor chain (sending their children) before selecting.
- JSON numbers come back from the parser as `Long` or `Double`; wire tests compare vectors as doubles.
- Value setters on nodes are no-ops when the value is unchanged, so a binder's `update` function can be written naively and still produce empty deltas.
- Line/point coordinates are rounded to 1e-5 on the wire: full-precision doubles made a 72-point orbit cost 6 KB instead of 1.5 KB.

## 4. Deviations from the design

1. **No binary upstream/downstream channel**: blobs are served over HTTP (`/wb/blob/`) with the browser cache instead of transport frames and IndexedDB; snapshots come back as base64 PNG in an event (fine for screenshots, not for 4K video frames).
2. **No `Sprite`, `extrude`/`lathe`/`text` geometries, cube/HDR textures (IBL), canvas-text textures, morph targets or glTF animation clips**; the glTF reader covers hierarchy, TRIANGLES primitives, metallic-roughness materials with base/normal/emissive textures, embedded buffers and images only.
3. **Drag constraints are evaluated in the parent's space on both sides**; the client's plane/axis solving assumes the parent frame is axis-aligned with the world (true for root-level nodes and unrotated groups).
4. **Hover effect `HIGHLIGHT`** clones the material per node on first hover (cheap for a few hundred nodes); there is no post-processing outline pass — selection and `OUTLINE` hover draw `EdgesGeometry` overlays, which is crisp for hard-edged meshes and busy on dense ones.
5. **Camera events** are sent when a gesture ends (and 200 ms after the last wheel tick), not at a fixed 200 ms rate during the gesture; the server's camera copy lags by one gesture.
6. `Label3D` is a plain DOM overlay (no `CSS2DRenderer` dependency); occlusion is a per-label raycast each frame, so keep occludable labels to a few dozen.
7. Delta history is not bypassed for `scene` calls while the UI is detached (the general replay rules of step 2 apply; a reconnect that misses history gets a full `reset`).
8. `DownloadService` from the standard-components design does not exist; `download(name, w, h)` saves client-side, `snapshot()` returns bytes for anything server-side.
9. `WebGL2` capability is reported in `ready` but not acted upon; the renderer does not downgrade settings by itself.

## 5. Notes for step 8 (sample app)

- The demo now exercises every module; the sample app can compose the same pieces (explorer + properties + charts + 3D + dialogs) into a themed product and should add the options/help pieces still deferred from step 5.
- Hosting three.js from the module jar means a 620 KB download for the first 3D window per browser cache; the Jetty front end should add gzip for `/wb/res/`.
- `BlobStore` is per JVM and bounded by size; a persistent/shared store (disk, S3) behind the same `getDefault()` lookup hook is the natural next step for large models.
